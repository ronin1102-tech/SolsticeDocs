## Root cause (single, structural)

`<canvas class="absolute inset-0">` does not size a *replaced* element: without intrinsic
`width`/`height` attributes, a canvas defaults to 300×150 and `inset-0` only positions it.
Every overlay canvas in the app is 300×150 on a 612×792 page. Consequences, all from this:

1. Annotation input region is 39% wide × 19% tall of the page (top-left); strokes ending
   outside the box never fire mouseup on the canvas → dropped.
2. `record()` divides by the canvas' own rect (300×150), so stored "PDF units" are actually
   zoom-squashed CSS pixels. Persistence contract broken at the source.
3. Redraw paints using PDF-units math into the 300×150 bitmap → visible only for x<300, y<150
   page-space; a restored annotation is stored but not painted where expected.

One fix (size overlay bitmaps to the rendered page, or CSS `width/height:100%` with
`getBoundingClientRect`-derived PDF-units math) closes #1, #2 and the paint half of #3.
